# 개발 로드맵 — HTML 이어붙이기 → ES 모듈 기반 프로그램

목표: 화면 결과는 그대로 두고, 코드 구조를 **안전하게 고칠 수 있는 형태**로 바꾼다.
실행 방식(파일 하나로 열리는 HTML, 포터블 exe)은 유지한다.

## 원칙
- **기능 변경과 구조 변경을 섞지 않는다.** 구조를 옮기는 커밋은 화면이 바뀌면 안 된다.
- 모든 단계는 `npm test`(회귀 검사)를 통과해야 한다. 기준 프레임은 의도한 화면 변경일 때만 `npm run test:update`로 갱신한다.
- 결정론 유지: 렌더 계산에는 `RL.rng` / 시간의 함수만 쓴다.

## 출발점 구조 (v0.5.7 이전)
`build.mjs`가 `src/*.js` 25개를 정해진 순서로 이어 붙여 HTML 하나를 만들었다. 모든 파일이 전역 `RL` 하나를 공유했다. (지금은 ES 모듈 + Vite — 2단계 참고)

의존 관계 (순환 없음):

```
gl ─┬─ batch ─┐
    ├─ builtins├─ engine ─┬─ 레이어 모듈 (wave fluid particle dot line beam surface shapes floaters robot neongeo laser rhythm)
    └─ fx ─────┘          ├─ presets
robot_mesh ──────────────── mod_robot
audio · export ─────────── ui ─ ui2
```

## 단계

### 1. 회귀 검사 ✅ (v0.5.7)
- `tests/regress.mjs`: 프리셋 14개 + 리듬 다중참여·기본 이펙트 케이스 × 3시점 = 45장.
  - 레이어 ID 고정(레이어 난수 시드가 ID에서 나오므로), UI와 분리된 엔진, SwiftShader(CPU) 렌더 → PC·GPU와 무관하게 같은 결과
  - 같은 조건 두 번 렌더 = 같은 프레임(결정론), 기준 프레임(`tests/golden.json`)과 비교, 하얗게 뜬 프레임 검출
- 실행: `npm test` (빌드 + 검사)

### 2. ES 모듈 전환
1. ✅ **빌드 도구 교체**: Vite + 단일 파일 출력(축약 없음). 결과물은 그대로 `app/RESONANCE_LAB.html` 하나. 개발 서버 `npm run dev`.
2. ✅ **import 연결**: 파일마다 `import { RL } from './core/rl.js'`, 파일 간 공유 이름(`$`·`h`, 셰이더 상수, mp4-muxer)은 명시적 import.
   진입점 `main.js`가 예전 순서대로 import. 회귀 검사 45장 비트 단위 일치(화면 변화 0).
3. ✅ **층별로 이름 있는 export로 교체**: `RL.xxx = ...` → `export const xxx`, 사용처는 `import * as <별칭> from '<파일>'`.
   gl → batch·builtins·fx → engine → shapes·robot_mesh → audio·export → ui·ui2, 층마다 한 커밋.
   구조 분석(스코프) 기반 변환 도구로 바꿔 지역 이름 충돌을 확인했고, 충돌은 없었음.
4. ✅ 레지스트리를 `core/registry.js`로 (`registry.modules`, `registry.presets`).
5. ✅ 전역 `RL`은 디버그 콘솔용 호환 등록(`Object.assign(RL, {...})`)으로만 남김. 새 코드는 import만 사용.
   `npm run lint`(ESLint)로 선언하지 않은 이름 사용을 막는다.

### 3. 타입 검사 ✅
- ✅ JSDoc 주석 + `tsc --checkJs` (`npm run typecheck`, 파일은 .js 그대로 검사만). 타입 정의는 `src/types/`
  (`rlab.d.ts`: 설정 항목·레이어 모듈·프로젝트 / `env.d.ts`: 데스크톱 연결 / `modules.d.ts`: CSS·가상 모듈).
  설정 항목은 정해진 키만 허용해 `deafult` 같은 오타를 잡는다. 엔진·레이어 모듈 전체 오류 0.
- ✅ 스키마 검사 `tests/schema.mjs` (`npm run test:schema`): id 중복, 범위 밖 기본값, 목록에 없는 선택 기본값,
  group·label 누락, 프리셋의 없는 레이어 종류·목록 밖 선택값을 실패로, 스키마에 없는 프리셋 값·범위 밖 프리셋 값은 참고로 출력.
- 보류: `ui.js`·`ui2.js` — 화면 메서드를 `App.prototype`에 나중에 붙이는 구조라 오류가 몰려 있어 `@ts-nocheck`.
  4단계에서 화면 구조를 정리하며 함께 푼다.
- 참고로 남은 것: 프리셋 s1_2·fx_hit의 파장 레이어에 지금 엔진이 쓰지 않는 값(`faceTrans`, `edgeReflect`)이 들어 있음. 화면 영향 없음.

### 4. 데스크톱 구조 정리 ✅ (v0.5.8)
- ✅ `desktop/main.cjs`는 연결만, 규칙은 `desktop/lib/`: `log.cjs`(rlab.log 한 파일, 1MB 넘김), `settings.cjs`(기본값 보정,
  임시 파일 → 바꿔치기), `files.cjs`(고른 폴더·파일만 쓰기, 파일 이름 정리, 프로젝트 크기 제한, 자동 보관),
  `encoder.cjs`(FFmpeg 인자·해상도 검사·작업 관리·전체 취소). lib 은 Electron 없이 시험할 수 있게 의존성을 인자로 받는다.
- ✅ 오류 기록 일원화: 메인 프로세스 오류, 화면 콘솔 오류, 화면이 보내는 기록(`rlabNative.log`, 1초 20줄 제한),
  출력 시작·완료·실패·취소가 모두 `rlab.log`에. 화면 쪽 진입점은 `src/core/report.js`.
- ✅ 씬 백업 자동 보관(교체·전체 삭제 직전).
- ✅ 검사: `tests/desktop.mjs`(npm test 포함), `tests/desktop_e2e.mjs`(실제 Electron 실행, 선택).
- 검토 결과 보류: 시뮬레이션 Web Worker 분리. 유체·파티클은 프레임마다 GPU 텍스처를 주고받고, 출력은 이미 프레임 단위로
  순서대로 돌아 결정론이 보장된다. 워커로 옮기면 GPU 자원을 넘기는 비용과 프레임 순서 관리가 늘어나는 데 비해,
  실제 병목(GPU 렌더·FFmpeg 인코딩)은 줄지 않는다. 화면이 멈추는 문제가 실제로 생기면 그 레이어만 다시 검토.

### 4-2. 화면 파일 정리 ✅
- ✅ `ui.js`·`ui2.js` → `src/app/` 기능별 파일 11개. 기능 파일은 `export const <기능> = { … }` 메서드 묶음이고
  `App.js`가 `Object.assign(App.prototype, …)`로 붙인다(이전과 같은 실행 구조 — 이름 겹침 없음 확인).
- ✅ 타입: 기능 파일은 `@satisfies {ThisType<App>}`로 this 를 App 으로, `types/app.d.ts`가 기능 파일 메서드 타입과
  화면 상태(씬 백업 목록·확대·되돌리기 기록 등)를 `App`에 합친다. 화면 파일 포함 전체 오류 0.
- ✅ `tests/ui.mjs` 화면 동작 검사 13개 — 정리 전·후 빌드 모두 통과.

## 알려진 사항
- 프리셋을 불러올 때마다 레이어 ID가 새로 만들어져, 같은 프리셋도 열 때마다 무작위 배치가 달라진다.
  저장한 프로젝트는 ID가 고정되므로 출력 결정론에는 영향 없음. (필요하면 프리셋 레이어 ID를 고정하는 옵션 검토)
- 선 굵기·빛 번짐 같은 크기 값은 문서 픽셀 기준이라, 문서 해상도를 바꾸면 상대 크기가 달라진다(미리보기 배율 변경은 무관).
